# Live Wakeword Testing Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task.

**Goal:** Add the approved Testing tab with archived-version selection, local microphone inference, sensitivity dialog, and a live threshold-colored graph.

**Architecture:** Reuse the existing checksum-validated model archive endpoints. Run microWakeWord feature extraction and model execution in a dedicated browser worker, using the reference project's JavaScript implementation with its license retained. Own microphone resources in a cancellable session, independently of page rendering.

**Tech Stack:** Vue 3, TypeScript, Web Audio AudioWorklet, Web Workers, SVG, Vitest.

**Spec:** Approved description in this conversation (2026-10-20).

## Global Constraints
- Testing is last in navigation; use the shared wakeword selection.
- Slight/Moderate/Very factors are 0.5/1/2 applied to `1 - (1 - cutoff) * factor`, clamped to 0.10–0.99; fallback base is 0.90.
- Audio never leaves the browser; no recording is saved or uploaded.
- Plot the smoothed probability used for comparison, a dashed threshold, and red segments strictly above threshold.
- Preserve source/license notices for reference-project code; no runtime dependency on the sibling checkout.

## Review Focus
- Late microphone permission or model-load completion after stop must not revive capture.
- Changing wakeword/version or leaving the page must stop tracks, audio, and worker.
- Missing/invalid metadata and unsupported models must produce actionable errors, not fake scores.
- Audio sample rates other than 16 kHz must be resampled continuously without gaps.
- Model lists beyond one API page must remain selectable; stale responses must be ignored.
